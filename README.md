# Task Tracker CLI

Task Tracker CLI — консольное приложение для управления задачами, написанное на языке Go.

Приложение позволяет создавать, изменять и удалять задачи, менять их статус и выводить список задач с фильтрацией. Все данные сохраняются локально в JSON-файле, поэтому задачи не теряются после завершения программы.

Проект создан для практического изучения:

- языка Go;
- разработки консольных приложений;
- работы с файлами;
- кодирования и декодирования JSON;
- обработки аргументов командной строки;
- обработки ошибок;
- написания автоматических тестов;
- организации разработки по Git Flow.

## Возможности

Приложение поддерживает:

- создание новых задач;
- автоматическую генерацию идентификатора задачи;
- просмотр всех задач;
- фильтрацию задач по статусу;
- изменение описания задачи;
- удаление задачи;
- перевод задачи в работу;
- завершение задачи;
- сохранение даты создания;
- сохранение даты последнего изменения;
- хранение данных в файле `tasks.json`;
- проверку входных данных;
- обработку ошибок;
- автоматические тесты.

## Требования

Для сборки и запуска проекта необходим Go версии 1.22 или новее.

Проверить установленную версию Go:

```bash
go version
```

Пример вывода:

```text
go version go1.22.2 linux/amd64
```

## Структура проекта

```text
task-tracker/
├── .gitignore
├── go.mod
├── main.go
├── main_test.go
├── storage_test.go
└── README.md
```

Назначение файлов:

- `main.go` — основная логика приложения и обработка команд;
- `main_test.go` — тесты операций над задачами;
- `storage_test.go` — тесты загрузки и сохранения данных;
- `go.mod` — описание Go-модуля;
- `.gitignore` — список файлов, которые Git не должен отслеживать;
- `README.md` — документация проекта;
- `tasks.json` — локальное хранилище задач, создаваемое во время работы программы.

Файл `tasks.json` не добавляется в Git, поскольку содержит локальные пользовательские данные.

## Использование

Общий формат команды:

```text
./task-cli <команда> [аргументы]
```

При запуске через `go run`:

```text
go run . <команда> [аргументы]
```

## Добавление задачи

Добавить новую задачу:

```bash
go run . add "Купить продукты"
```

Пример вывода:

```text
Задача добавлена (ID: 1)
```

Описание обязательно. Пустое описание или строка, состоящая только из пробелов, не принимается.

Можно передать описание без кавычек:

```bash
go run . add Купить продукты
```

Все слова после команды `add` будут объединены в одно описание. Однако кавычки делают команду понятнее и безопаснее для оболочки.

Новая задача получает статус `todo`.

## Просмотр задач

Показать все задачи:

```bash
go run . list
```

Пример вывода:

```text
1. [todo] Купить продукты
2. [in-progress] Изучить тестирование
3. [done] Создать Go-модуль
```

Если задач нет:

```text
Задач нет.
```

## Фильтрация по статусу

Показать задачи со статусом `todo`:

```bash
go run . list todo
```

Показать задачи со статусом `in-progress`:

```bash
go run . list in-progress
```

Показать выполненные задачи:

```bash
go run . list done
```

Поддерживаются только три статуса:

| Статус | Значение |
|---|---|
| `todo` | задача создана, но работа ещё не начата |
| `in-progress` | задача находится в работе |
| `done` | задача выполнена |

## Изменение задачи

Изменить описание задачи:

```bash
go run . update 1 "Купить продукты и воду"
```

Пример вывода:

```text
Задача 1 обновлена
```

Первый аргумент после `update` — идентификатор задачи. Остальные аргументы образуют новое описание.

При обновлении задачи поле `updatedAt` получает новое время.

## Удаление задачи

Удалить задачу:

```bash
go run . delete 1
```

Пример вывода:

```text
Задача 1 удалена
```

Если задачи с указанным идентификатором нет, программа завершится с сообщением об ошибке.

## Перевод задачи в работу

Изменить статус задачи на `in-progress`:

```bash
go run . mark-in-progress 1
```

Пример вывода:

```text
Задача 1 отмечена как in-progress
```

## Завершение задачи

Изменить статус задачи на `done`:

```bash
go run . mark-done 1
```

Пример вывода:

```text
Задача 1 отмечена как done
```

## Список команд

| Команда | Назначение |
|---|---|
| `add "описание"` | добавить новую задачу |
| `list` | показать все задачи |
| `list todo` | показать задачи со статусом `todo` |
| `list in-progress` | показать задачи в работе |
| `list done` | показать выполненные задачи |
| `update <id> "описание"` | изменить описание задачи |
| `delete <id>` | удалить задачу |
| `mark-in-progress <id>` | перевести задачу в работу |
| `mark-done <id>` | отметить задачу как выполненную |
| `--help` | показать справку |
| `-h` | показать справку |

## Хранение данных

Задачи сохраняются в файле:

```text
tasks.json
```

Если файл отсутствует, приложение создаёт его автоматически при выполнении команды, работающей с задачами.

Пример содержимого файла:

```json
[
  {
    "id": 1,
    "description": "Купить продукты",
    "status": "todo",
    "createdAt": "2026-10-27T07:22:03.888979897Z",
    "updatedAt": "2026-10-27T07:22:03.888979897Z"
  }
]
```

Поля задачи:

| Поле | Тип | Описание |
|---|---|---|
| `id` | число | уникальный идентификатор задачи |
| `description` | строка | описание задачи |
| `status` | строка | текущий статус |
| `createdAt` | дата и время | время создания |
| `updatedAt` | дата и время | время последнего изменения |

Дата и время сохраняются в формате UTC.

Не рекомендуется изменять `tasks.json` вручную. Некорректный JSON не сможет быть загружен приложением.

## Проверка входных данных

Приложение проверяет:

- идентификатор должен быть положительным числом;
- описание не должно быть пустым;
- задача с указанным идентификатором должна существовать;
- статус должен быть одним из допустимых;
- JSON-файл должен содержать корректные данные.

При ошибке сообщение выводится в стандартный поток ошибок, а программа завершается с ненулевым кодом.

## Тестирование

Запустить все тесты:

```bash
go test ./...
```

Запустить тесты с подробным выводом:

```bash
go test -v ./...
```

```bash

```

Перед фиксацией изменений рекомендуется выполнить:

```bash
gofmt -w main.go main_test.go storage_test.go

```

## Git Flow

Разработка проекта выполняется по Git Flow.

Основные ветки:

- `main` — стабильная версия проекта;
- `develop` — текущая версия разработки;
- `feature/*` — разработка отдельных возможностей;
- `release/*` — подготовка релиза;
- `hotfix/*` — срочные исправления стабильной версии.

Пример создания новой функциональной ветки:

```bash
git switch develop
git switch -c feature/example
```

После завершения работы:

```bash
git add .
git commit -m "feat: add example"
git switch develop
git merge --no-ff feature/example -m "merge: example"
git branch -d feature/example
```
